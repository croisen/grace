GRACE — wiring the Rust syntax drills into the app
Folder: grace/rust/src/api/drills/rust
For: whoever owns the Flutter side

What this folder is
-------------------
These files only GENERATE a drill. They do not check an answer, score it,
or schedule the next one. Each call returns a fresh random exercise.

Show `conditions` to the student. That is the prompt.
Hide `answer`. That is the expected code, for the checker only.
The variable drill is the exception: its code lives in `code`, not `answer`.

Nothing here has to be moved. `src/api/mod.rs` already has `pub mod drills`,
and `drills/mod.rs` already has `pub mod rust`. flutter_rust_bridge scans
`crate::api`, so these public functions are already on the bridge surface.
Private helpers (`callsign`, `distinct_callsigns`) are not exported. Leave
them private.

Generators
----------
Rust call                                      Dart name after codegen
---------------------------------------------  ---------------------------
if_statement::generate_if_statement()          generateIfStatement()
else_if::generate_else_if()                    generateElseIf()
match_statement::generate_match_statement()    generateMatchStatement()
while_statement::generate_while_statement()    generateWhileStatement()
for_statement::generate_for_statement()        generateForStatement()
loop_statement::generate_loop_statement()      generateLoopStatement()
function::generate_function()                  generateFunction()
variable::generate_variable(choice, if_mut)    generateVariable(choice, ifMut)
variable::generate_distinct_variables(...)     generateDistinctVariables(...)

Do not build the screen on generateVariable / generateDistinctVariables.
Those exist so the other drills can build declarations. The screen should
call one of the seven concept generators.

What you get back
-----------------
Every concept drill is a struct with two Strings:

    answer       full Rust snippet, including any `let` lines it needs
    conditions   the prompt, one bullet per line

VariableDrill is different:

    code         the `let` line
    conditions   bullets for name, type, value, mutability
    name         identifier, e.g. "alpha"
    state        "" or " mut"
    var_type     "String" or "i32"
    value        the raw value, no quotes

generate_variable arguments, if you do call it directly:

    choice   0 = String, 1 = i32, anything else = String
    if_mut   0 = not mutable, 1 = mutable, anything else = "may or may not"
             (the code still omits `mut` unless if_mut is 1)

What each concept drill emits
-----------------------------
generate_if_statement
    Two immutable i32 lets, then if / else.
    True branch prints pass, false branch prints fail.

generate_else_if
    Three immutable i32 lets, then if / else if / else.
    Prints pass, retry, or fail.

generate_match_statement
    One immutable i32 let, then match.
    Two numeric arms (0 through 9, sorted) print pass and retry.
    `_` prints fail.

generate_while_statement
    One immutable i32 let, then while <name> <op> <0..=20>.
    Body prints pass.

generate_for_statement
    No let. `for <name> in <start>..<end>` with end > start.
    Body prints pass. The range is exclusive.

generate_loop_statement
    One mutable i32 let, then loop.
    Breaks when `<name> <op> <0..=20>`, otherwise prints pass.

generate_function
    One of four shapes, chosen at random:
      fn name() { println!("pass"); }
      fn name(param: i32) -> i32 { return param; }
      fn name(left: i32, right: i32) -> i32 { return left + right; }
      fn name(param: String) { println!("pass"); }

Names come from the NATO alphabet in mod.rs (alpha ... zulu).
Operators are only ==, <=, >=, <, >. There is no !=.
Calling a generator again makes a new drill. There is no seed.

Step 1. Mark the functions sync
-------------------------------
Copy the attribute already used on `greet` in src/api/simple.rs.
Put it on every public generator the app will call. Example:

    use flutter_rust_bridge::frb;

    #[frb(sync)]
    pub fn generate_if_statement() -> IfStatementDrill {

Do that for:
    generate_if_statement
    generate_else_if
    generate_match_statement
    generate_while_statement
    generate_for_statement
    generate_loop_statement
    generate_function

Without #[frb(sync)], Dart receives a Future and you must await it.
That also works. Sync matches greet and these functions are cheap.
Do not annotate callsign, distinct_callsigns, or the private function_* helpers.

Step 2. Regenerate the bridge
-----------------------------
From the Flutter app root (the project that already generates greet),
run the same command you already use. In a stock FRB 2.13 app that is:

    flutter_rust_bridge_codegen generate

It reads flutter_rust_bridge.yaml. rust_input should already be crate::api.
Do not add a second rust_input just for drills. Submodules are included.

Generated Dart shows up next to the file that contains greet
(api/simple.dart), under:

    api/drills/rust/if_statement.dart
    api/drills/rust/else_if.dart
    api/drills/rust/match_statement.dart
    api/drills/rust/while_statement.dart
    api/drills/rust/for_statement.dart
    api/drills/rust/loop_statement.dart
    api/drills/rust/function.dart
    api/drills/rust/variable.dart

The exact folder is whatever `dart_output` says in that yaml.
A full restart is required after codegen. Hot reload will not pick up
new native symbols.

Step 3. Call it from Dart
-------------------------
RustLib.init() is already done at startup if greet works. Do not init again.

    import 'package:YOUR_APP/src/rust/api/drills/rust/if_statement.dart';

    final drill = generateIfStatement();
    final prompt = drill.conditions; // show this
    final key = drill.answer;        // keep this off the screen

Same pattern for the others:

    final drill = generateElseIf();
    final drill = generateMatchStatement();
    final drill = generateWhileStatement();
    final drill = generateForStatement();
    final drill = generateLoopStatement();
    final drill = generateFunction();

If you skipped #[frb(sync)], every one of those is:

    final drill = await generateIfStatement();

A screen only needs the prompt string and a text field. Suggested flow:

    1. User picks a concept (if, else if, match, while, for, loop, function).
    2. Call the matching generator once.
    3. Put conditions in the prompt widget.
    4. Keep answer in memory, not in the widget tree.
    5. On submit, hand answer and the student's text to the checker
       (not part of this folder).
    6. On "next", call the generator again. Do not reuse the old struct.

Rust-side smoke call, if you want it before Flutter
---------------------------------------------------
From anywhere inside the crate:

    use crate::api::drills::rust::for_statement::generate_for_statement;

    let drill = generate_for_statement();
    println!("{}", drill.conditions);
    println!("{}", drill.answer);

Or, from grace/rust:

    cargo test --bin rust-lib-grace -- generators_produce_syntax_and_conditions

That test calls every generator 40 times. "1 passed" means the files compile
and the strings are non-empty. It does not mean the Flutter binding exists yet.
